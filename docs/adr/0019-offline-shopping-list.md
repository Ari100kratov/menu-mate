# 0019 Офлайн-режим списка покупок

## Статус

Принято.

## Контекст

Список покупок используется в магазине, где связь может пропасть до открытия приложения или во время работы. Пользователь должен видеть последний загруженный список, менять отметки и не терять их после перезагрузки страницы. При этом access-token по принятой auth-стратегии хранится только в памяти, а сервер остается источником истины.

## Решение

- Service worker предварительно кеширует только оболочку frontend-приложения и статические ресурсы. Запросы `/api`, `/openapi` и `/scalar` не попадают в runtime-кеш.
- Последний подтвержденный список, профиль пользователя и очередь итоговых отметок сохраняются в IndexedDB. Это устройство-зависимая рабочая копия, а не новый источник истины.
- Access-token и refresh-token в IndexedDB не сохраняются. Холодный офлайн-запуск создает ограниченную локальную сессию, которая открывает только `/shopping`.
- Без сети доступны просмотр, сворачивание категорий, шаринг и переключение отметок. Добавление, редактирование, удаление и генерация из меню блокируются.
- Повторные переключения одной позиции сжимаются до конечного состояния. После восстановления сессии frontend получает актуальный список и последовательно отправляет итоговые состояния через существующий idempotent endpoint отметки.
- Локальное состояние побеждает только для позиций, измененных офлайн. Удаленные на сервере позиции пропускаются с уведомлением; остальные серверные изменения сохраняются.
- Явный выход очищает локальную рабочую копию. Кеш другого пользователя не показывается после нового входа.

## Последствия

Первый офлайн-запуск возможен только после успешного онлайн-посещения, при котором установился service worker и сохранился список. Синхронизация выполняется в открытом приложении или при следующем запуске онлайн; Background Sync не требуется. Приватность локальной копии соответствует доверию к браузерному профилю устройства.
