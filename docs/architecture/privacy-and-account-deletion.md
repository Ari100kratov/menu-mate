# Конфиденциальность и удаление аккаунта

## Публичные страницы

- `/privacy` — политика конфиденциальности;
- `/account-deletion` — инструкция по удалению в приложении и запросу удаления без доступа к аккаунту;
- `GET /api/legal/privacy-policy` — публичные реквизиты текущей версии.

Обе страницы открываются без авторизации. Для Google Play в поле privacy policy указывается полный HTTPS URL `/privacy`, а в поле удаления аккаунта — полный HTTPS URL `/account-deletion`. Страница политики должна быть активной, общедоступной, не требовать входа, не иметь географической блокировки и отдаваться как HTML, а не PDF.

## Версия и принятие

Текущая версия задается в `PrivacyPolicyDefaults`. Регистрация передает ее в `RegisterUserRequest`. Backend является источником истины: если клиент отправил иную версию, возвращается `Auth.PrivacyPolicyOutdated`.

В `auth.users` хранятся:

- `privacy_policy_accepted_version`;
- `privacy_policy_accepted_at`.

Для существующих пользователей оба поля после миграции пусты. Профиль возвращает `requiresPrivacyPolicyAcceptance`; web-клиент направляет такого пользователя на `/privacy/accept`. При изменении существенного текста нужно:

1. обновить текст публичной страницы;
2. изменить `PrivacyPolicyDefaults.CurrentVersion` и `EffectiveAt`;
3. обновить тестовые ожидания;
4. развернуть API и web одной версией.

## Семантика удаления данных

Endpoint `POST /api/auth/me/delete` принимает текущий пароль. Модули очищаются до удаления учетной записи:

1. RecipeImports: черновики и исходные объекты;
2. MenuPlanning: позиции календаря и приемы пищи;
3. ShoppingLists: список и его позиции;
4. Recipes: библиотека пользователя, чужие закладки удаляемых оригиналов, собственные рецепты, ревизии и изображения;
5. Auth: роли, refresh token, account action и пользователь.

Глобальные продукты и теги не принадлежат пользователю и не удаляются. Независимые копии рецептов других пользователей сохраняются. Офлайн-копия списка покупок очищается web-клиентом после успешного ответа.

Объектное хранилище и несколько схем PostgreSQL не образуют единую транзакцию. Поэтому очистители идемпотентны, а Auth удаляется последним. Ошибка одного шага возвращает ошибку и сохраняет аккаунт, чтобы запрос можно было повторить.

## Конфигурация оператора

В production обязательны:

```dotenv
LEGAL_OPERATOR_NAME=<полное имя организации, ИП или владельца сервиса>
LEGAL_PRIVACY_CONTACT_EMAIL=privacy@example.com
LEGAL_TECHNICAL_LOG_RETENTION_DAYS=30
LEGAL_BACKUP_RETENTION_DAYS=30
```

Сроки нельзя указывать условно: Docker logs, reverse proxy, Aspire/внешняя телеметрия и резервные копии должны быть настроены на те же или меньшие значения. Если фактический состав провайдеров отличается от текста страницы, текст политики необходимо обновить до релиза.

## Чек-лист Google Play

- указать публичные HTTPS URL политики и удаления аккаунта;
- заполнить Data Safety по фактическим данным, SDK и внешним сервисам;
- проверить удаление из установленного Android-клиента и по внешней ссылке;
- указать в политике оператора, контакт, категории данных, цели, получателей, защиту, сроки и правила удаления;
- проверить, нужен ли отдельный экран раскрытия и согласия для чувствительных данных, которые используются неочевидным для пользователя способом;
- провести юридическую проверку текста для стран распространения. Техническая реализация не заменяет юридическую консультацию.
