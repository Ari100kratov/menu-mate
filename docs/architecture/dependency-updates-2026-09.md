# Обновление зависимостей: сентябрь 2026

Версии проверены в реестрах npm и NuGet. Обновлены прямые зависимости в пределах текущих основных версий, а также транзитивные зависимости фронтенда в `pnpm-lock.yaml`.

- .NET остается на `net10.0`. Минимальная версия SDK — 10.0.300; `latestFeature` разрешает установленные более новые feature band .NET 10, включая 10.0.400, без перехода на .NET 11.
- Пакеты ASP.NET Core и EF Core: 10.0.11; Extensions Resilience и ServiceDiscovery: 10.9.0.
- Aspire и Aspire.AppHost.Sdk синхронизированы на 13.5.3; OpenTelemetry: 1.18.0; OpenAI SDK: 2.13.0.
- Обновлены Scalar, SonarAnalyzer, Testcontainers и Microsoft.NET.Test.Sdk.
- Обновлены React, Radix, TanStack, Tailwind, Vite, ESLint и остальные пакеты, для которых доступны совместимые обновления. pnpm закреплен на 11.19.0.
- TypeScript остается на 5.9.3, Vitest на 4.1.11, xunit.runner.visualstudio на 3.1.5. Новые основные версии (TypeScript 7, Vitest 5, runner 4) не входят в это совместимое обновление. Пакеты без новых совместимых версий оставлены без изменения.

Публичные HTTP-контракты, целевая платформа и схема базы данных сохранены. Новое правило анализатора учтено передачей `RequestAborted` при записи ответа авторизации.

Проверки выполняются без запуска приложения. Тесты генерации обложек используют подмененный HTTP-транспорт и не обращаются к OpenAI. Интеграционные тесты API требуют Docker/PostgreSQL и отдельной проверки окружения.

Для транзитивных `glob@11`, `fast-uri@3` и `browserslist@4` в `pnpm-workspace.yaml` заданы совместимые исправленные версии: 11.1.0, 3.1.6 и 4.28.9 соответственно. Обычное рекурсивное обновление оставляло уязвимые версии в цепочке Workbox/Babel/Ajv. Переопределения следует пересматривать вместе с обновлениями PWA-инструментов.

## Проверка после слияния Dependabot, 13 сентября

В текущей ветке также проверены слитые обновления Vitest 5 и xunit.runner.visualstudio 4. Сборка решения Release прошла с прежним ASPIRE010; все 186 модульных тестов .NET и 38 интеграционных тестов прошли. Интеграционные тесты использовали временную PostgreSQL и тестовый сервер внутри процесса; обычный запуск приложения не выполнялся.

Для npm в Dependabot явно задан `cooldown.default-days: 3`. В `pnpm-workspace.yaml` явно установлен `minimumReleaseAge: 0`: автоматическая проверка возраста в pnpm 11 применяется также к транзитивным версиям готового lockfile, которые Dependabot может выбрать при обновлении. Один только cooldown прямых зависимостей не гарантирует возраст всего транзитивного дерева. Источники: [настройки pnpm](https://pnpm.io/settings#minimumreleaseage), [описание cooldown Dependabot](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference#cooldown).

Компромисс: задержка остается у плановых обновлений Dependabot, но локальные установки и транзитивные зависимости больше не ограничиваются возрастом средствами pnpm. `--frozen-lockfile`, контроль целостности пакетов и сканирование уязвимостей сохраняются. Lockfile не пересоздается автоматически в CI, исключений по автору PR нет. Срочные обновления безопасности могут обходить cooldown по правилам Dependabot.

В frontend CI добавлен `pnpm test`. Для регрессионных тестов компонентов в DOM добавлен jsdom; запуск веб-сервера для этих тестов не нужен.

Итоговые проверки фронтенда: `pnpm install --frozen-lockfile`, `pnpm format`, `pnpm lint`, `pnpm typecheck`, `pnpm test` (27 тестов) и `pnpm build` прошли. Осталось предупреждение Vite о JS-файле около 600 КБ. `git diff --check` не выявил ошибок пробелов. Проверка закрытия конкретных предупреждений CodeQL остается за повторным сканированием GitHub.
